# Blog Publishing Rules — Omdan Development Inc

These rules govern every article generated by the weekly blog automation.
The publish script (`scripts/publish-blog.js`) enforces the technical rules automatically.
This file documents the editorial standards Claude must follow when generating content.

---

## Topic source

- Topics come exclusively from `/content/blog-topic-library.json`.
- Topics already logged in `/content/blog-posted-log.json` must never be reused.
- Selection order: highest `priority` value first. Equal priority → earlier position in the library.
- If the library is exhausted, the script exits cleanly without publishing.

---

## Topic library format

Each entry in `blog-topic-library.json`:

```json
{
  "title": "Full article title as it will appear on the page",
  "slug": "url-friendly-slug-matching-the-title",
  "category": "Service category label shown on the badge",
  "priority": 10,
  "city": "Optional — primary city focus e.g. Palm Springs",
  "service": "Optional — primary service e.g. pavers"
}
```

Priority scale: `10` = highest (publish first), `1` = lowest. Use whole numbers.

---

## Writing standards

**Voice and accuracy**
- Write as a knowledgeable local contractor, not as a generic content mill.
- No fake customer testimonials or invented stories.
- No made-up statistics or specific numbers that cannot be verified.
- No pricing. Not even ranges.
- Do not write "as a homeowner you know..." or similar assumed-experience openers.

**Length and structure**
- Minimum 5 sections, maximum 7.
- Each section: 2–4 paragraphs.
- Total article length: approximately 900–1,400 words in the body.
- At least one FAQ section (4–5 questions).

**SEO requirements**
- Unique `<title>` tag per article (format: `Article Title | Omdan Development`).
- Unique `meta description`: 140–160 characters, includes the primary keyword naturally.
- `<link rel="canonical">` pointing to the article's own URL.
- Internal links to relevant service pages where contextually natural.
- Mention at least one specific city or service area relevant to the topic.

**Internal link targets** (only link to pages that exist):
- `/pavers/` — paver installation
- `/artificial-turf/` — artificial turf
- `/concrete/` — concrete work

- `/kitchen-remodeling/` — kitchen remodeling
- `/bathroom-remodeling/` — bathroom remodeling

- `/exterior-painting/` — exterior painting

## HTML and schema requirements

- Article page must match the structure of `blog/how-artificial-turf-saves-money/index.html` exactly.
- Include `BlogPosting` JSON-LD schema with: headline, description, url, datePublished, dateModified, author, publisher, image, keywords, articleSection.
- Include `FAQPage` JSON-LD schema with all FAQ items.
- Article body uses `.prose-article` class for typography styling — do not add inline styles to body text.
- CTA block at the end of every article: links to the most relevant service page, never to `/blog/` or `/#contact` alone.

---

## Automatic updates on every publish

The publish script handles all of these — do not skip any:

1. Write `blog/SLUG/index.html` — the new article page.
2. Update `blog/index.html` — prepend new card to the post grid via `<!-- BLOG:CARDS -->` marker; update `blogPost` array in the Blog JSON-LD.
3. Update `sitemap.xml` — add new `<url>` entry with today's date, `monthly` changefreq, priority `0.7`.
4. Append to `content/blog-posted-log.json` — record title, slug, and date_posted.
5. Commit and push to `main` — commit message format: `feat(blog): auto-publish — TITLE`.

---

## What the `<!-- BLOG:CARDS -->` marker does

The marker `<!-- BLOG:CARDS -->` sits inside the post grid in `blog/index.html`.
The publish script inserts each new card immediately after this marker so posts appear newest-first.
Do not remove or move this marker.
